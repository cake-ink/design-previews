Booking several sittings in one pass

“it needs to be really easy for an artist to book multiple sessions for one client, and that currently doesn’t exist in the app, so we need to think through ways to actually build this in” Micah, 2026-10-22 · CAK-1759

Three shapes for Quick add, drawn at the width she meets them. All three assume CAK-1728 has landed, which puts the Time offers chosen list into Quick add — so the question is not whether she gets a list, but what she does with it. The client, the piece and the deposit are set once above the times in every shape.

Storage already allows this: sessions.request_id is a non-unique index, so N sittings against one request need no migration.

The calls behind the drawings

A and C are not rivals

C is A with a generator bolted above the same list. Every date it writes lands in A’s list and is editable there, so building A first and adding C later costs nothing extra.

Recommendation: ship A, then add C. A is the shape that makes several sittings possible; C is the shape that makes it fast.

Why B is drawn but not recommended

It reads best cold, and it is the only shape that gives each sitting its own length without a sheet. But it is a second time-picking layout, which the 2026-10-21 ruling and CAK-1728 exist specifically to prevent.

If per-sitting length matters more than the layout ruling, that is Micah’s call to make, not this preview’s.

The clash has to name the sitting

With one session a refusal can say “that time is taken”. With four it must say which, or she has to find it herself. C shows the shape: the notice names the date and offers the nudge.

This is why the conflict check runs per sitting rather than over the set.

The cap, and the count

Drawn as 6 here, against Time offers’ 8. The count sits beside the heading and turns amber near the limit, exactly as CAK-1630 settled it for day chips.

Four or six both read fine at this width. A longer piece can take a second booking.

One deposit, one client, told once

All three set the client, the piece and the deposit above the times, because those belong to the piece rather than to a sitting. That is also CAK-1429’s fix: the deposit stops being credited to whichever sitting happens to be last.

What a single sitting looks like

Unchanged, in all three. With one row the list is one row, the count reads 1 of 6, and the button says Book it now as it does today.

A single booking must not get slower or wordier to make room for this.
